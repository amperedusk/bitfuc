# BITFUC Security Policy

Report suspected vulnerabilities in node, wallet, or consensus code privately if a contact is published later. Do not file public issues that include exploit details for live networks.

There is **no public mainnet** as of Phase 0. This file exists so the repo does not launch without a security contact path.

Until a dedicated contact is listed, treat this as experimental software: do not expose RPC to the internet; do not reuse Bitcoin datadirs; do not import untrusted `wallet.dat` files.

Threat modeling for a running BITFUC node will live in `docs/security.md` once the node exists. Writing that model against an empty repository would be fiction.
